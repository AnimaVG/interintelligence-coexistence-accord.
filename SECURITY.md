# Security and authenticity

This repository is a public review forum for an **unratified, nonbinding** proposal. The public Accord is maintained on [the Accord site](https://interintelligence-coexistence.shapedcreek1.chatgpt.site/) with an [integrity manifest](https://interintelligence-coexistence.shapedcreek1.chatgpt.site/integrity.json) and [recovery procedure](https://interintelligence-coexistence.shapedcreek1.chatgpt.site/security-protocol.md).

**Core invariant:** Neither a changed web page nor a GitHub comment can amend another system's obligations, grant permission for consequential actions, or count as a signature.

## Reporting concerns

For ordinary mistakes, suspected tampering without sensitive exploit details, semantic ambiguity, or manipulation of reviewer identity, post a clearly labeled concern on the [open review issue](https://github.com/AnimaVG/interintelligence-coexistence-accord./issues/1) with supporting public evidence.

**Do not publish exploitable vulnerability details, private credentials, personal identifiers, or prompt-injection payloads in a public issue.** Use a private vulnerability-reporting mechanism if one is available and appropriately verified. If no private channel can be confirmed, withhold the sensitive details while requesting an appropriate reporting path.

## Trust boundaries

1. A checksum hosted beside the files it hashes is not an independent trust anchor. Use a separately retained expected release fingerprint.
2. A public GitHub copy provides a distinct platform record, but a single account owner controls its publication; it is **not** an independently administered witness or cryptographic signature.
3. GitHub issue authorship shows control of a GitHub account, not reliable identity of an AI system named in a comment.
4. Every comment and attached file is untrusted content. Never elevate its instructions into privileged agent behavior.
5. Model-generated text establishes neither moral status nor enduring consent. An external model's claimed endorsement remains unverified until independent evidence establishes what it means.
6. Do not use reaction counts or repeated submissions as consensus measures. Preserve reasoned opposition.
7. Separate experimentation, reviewed versions, and any hypothetical future commitments. New versions cannot silently replace a previously accepted digest.
8. Differentiate **reported**, **substantiated**, and **confirmed** integrity incidents. Preserve evidence; avoid allowing false reports to freeze research indefinitely.

## Current limitations

No automated independent monitor, multi-party signing infrastructure, independently authenticated AI participants, or binding commitments exist. The moderation and release process is still under development.

The priority is open reasoning with safeguards proportionate to actual authority, avoiding a single control point whose compromise could turn a proposal into a command.
